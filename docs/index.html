L’IA qui agit, l’humain qui décide.

Deux outils libres pour automatiser le travail sans en perdre le contrôle : un agent de code qui demande avant d’écrire, et des workflows où une personne valide les étapes qui comptent.

  • CSAgent L’agent de code qui demande d’abord. Windows, Linux, macOS. Découvrir CSAgent
  • CSFlow Les workflows où l’humain garde la main. Python et YAML. Découvrir CSFlow

Pourquoi ces deux projets

Les assistants d’IA savent déjà lire du code, écrire des fichiers et lancer des commandes. Le difficile est de leur laisser ce pouvoir sans y perdre en confiance. Ces projets partent de trois convictions.

  • Voir, puis autoriserUn agent qui modifie vos fichiers doit montrer ce qu’il fait et attendre votre accord. CSAgent confirme les actions destructrices, restreint les chemins et filtre les commandes dangereuses.
  • Les chiffres ne se devinent pasDans un processus métier, un calcul doit être exact. CSFlow confie les calculs à Python et réserve l’IA à ce qu’elle fait bien : lire des notes libres, rédiger, proposer une correction.
  • Rester maître de ses outilsCSAgent s’appuie sur la seule bibliothèque de base de .NET, sans dépendance NuGet, et parle à tout serveur compatible OpenAI (API Albert, Ollama, OpenRouter). CSFlow se livre en un exécutable qui n’exige pas Python.

Projet 1 : agent de code

CSAgent, l’agent de code qui demande d’abord

La raison d’être. Un agent autonome est utile quand on peut lui confier une tâche sans surveiller chaque geste, et dangereux quand on ne sait pas ce qu’il a touché. CSAgent lit, modifie et exécute des choses dans votre dossier, pas à pas, et demande avant d’écrire, de déplacer ou de supprimer.

Il se contente d’une clé d’accès à un serveur compatible OpenAI : on choisit son modèle, y compris un modèle local, plutôt que de dépendre d’un seul fournisseur.

Ce qu’il sait faire

  • Quatre façons de l’utiliser : terminal, interface web, interface légère, et mode API sans interface pour les orchestrateurs.
  • 43 outils intégrés : fichiers, shell, git, recherche, audio, e-mail, avec confirmation des actions destructrices.
  • Client de serveurs MCP : branchez-lui d’autres outils, dont CSFlow.
  • Mémoire qui limite l’amnésie sur les longues sessions, et skills (fiches de procédures) chargées à la demande.
  • Choix automatique du modèle, reprise après les erreurs 429, passage derrière un proxy d’entreprise.

Projet 2 : orchestrateur de workflows

CSFlow, les workflows où l’humain garde la main

La raison d’être. Beaucoup de tâches mêlent trois ingrédients : un calcul qui doit être juste, un texte qu’il faut lire ou rédiger, et une décision qui revient à une personne. CSFlow les enchaîne dans un simple fichier YAML : Python calcule, CSAgent raisonne, l’humain valide.

Exemple fourni : préparer un comité de pilotage. Les indicateurs sont calculés exactement, l’agent tire risques et actions de notes libres, et rien n’est diffusé sans l’accord du chef de projet.

Ce qu’il sait faire

  • Workflows en YAML, relisibles en revue de code, avec onze types d’étapes : agent, shell, python, fichiers, HTTP, validation humaine…
  • Branches conditionnelles et variables d’une étape à l’autre.
  • Vérification avant lancement (types inconnus, clés mal écrites, étapes manquantes), avec complétion dans VS Code.
  • Interface graphique : graphe du workflow, détail de chaque étape, éditeur YAML, journal en direct, pensée pour l’accessibilité au clavier.
  • Exécutable unique sans Python à installer, pour Windows et Linux.
  • Mode MCP : CSAgent peut lister, vérifier et lancer vos workflows.

Mieux ensemble : CSAgent pilote CSFlow

Grâce au protocole MCP, vous demandez en langage naturel « lance le rapport de ventes » : CSAgent liste les workflows, en lance un et vous rend compte à chaque étape. Les étapes qui demandent de l’intelligence repartent vers CSAgent.

  1. VousDemandez en français ou en anglais.
  2. CSAgent interactifVous demande la permission pour chaque appel.
  3. CSFlowExécute le workflow étape par étape (mode MCP).
  4. CSAgent workerTraite les étapes qui demandent du raisonnement.

À savoir. Un workflow qui contient une validation humaine n’est jamais lancé par l’agent : vous l’ouvrez dans l’interface de CSFlow et vous approuvez vous-même. Les étapes shell et python d’un workflow ne passent pas par le filtre de commandes de CSAgent : réservez ce mode à des workflows de confiance.
